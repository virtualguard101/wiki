# 汇编控制流

> [Computing 101. - Control Flow | pwn.college](https://pwn.college/computing-101/control-flow/)
>
> [调用约定 | 维基百科](https://zh.wikipedia.org/wiki/%E8%B0%83%E7%94%A8%E7%BA%A6%E5%AE%9A)

在机器指令层面, 控制流指的是 CPU 下一条执行哪条指令. 默认顺序执行, `cmp` 加条件跳转实现分支与循环, `call` / `ret` 实现函数调用.

阅读本文前, 建议先掌握以下前置知识: [x86-64汇编基础](x86-64汇编基础.md#算术比较与标志位), [栈与程序参数](栈与程序参数.md)与[指针访存的汇编描述](指针访存的汇编描述.md).

在[逆向工程](../../cyber/re/程序控制流的逆向分析.md)中, 理解汇编控制流尤为重要, 因为它直接对应着高层语言的逻辑结构.

## 比较与标志位

`cmp a, b` 计算 `a - b` 但不保存结果, 只更新标志位(如 ZF). 之后用 `setz` / `setnz` 把标志写入字节寄存器, 或用条件跳转消费它.

```asm
cmp QWORD PTR [rsp], 42   # [rsp] 是 argc
setz dil                  # argc == 42 则 dil = 1
mov eax, 60
syscall                   # exit(rdi), 退出码只取低 8 位
```

- `cmp` 两个操作数最多一个是内存, 不能内存对内存.

- `setz dil` 只写 `rdi` 的低字节, 退出码只看低 8 位, 所以够用. 寄存器的子视图见[寄存器](x86-64汇编基础.md#寄存器).

- 内存操作数要写明[宽度](指针访存的汇编描述.md#访问宽度).

## 分支与循环

`jmp` 无条件跳转, `je` / `jne` 等依据标志位跳转. 向后跳就形成循环.

循环需要三样东西: 当前位置, 进度, 结束判断. 以 `strlen(argv[1])` 为例:

```asm
mov rax, [rsp+16]         # rax = argv[1]
mov rdi, 0                # 计数器
loop:
    cmp BYTE PTR [rax], 0 # 是否到 \0
    je done
    inc rax               # 位置前进
    inc rdi               # 进度加一
    jmp loop              # 向后跳
done:
    mov eax, 60
    syscall
```

这里 `cmp` 只负责检测 `\0', `rdi` 只是计数器. `rax` 存的是地址, 所以必须用 64 位视图, 并用 `[rax]` 解引用取字节. 参数布局在[汇编视角下的程序参数传递](栈与程序参数.md#汇编视角下的程序参数传递)已经有所说明.

## 跳转表

条件分支的常规写法(`cmp` + `jcc`)与其逆向分析可参考[条件分支](../../cyber/re/程序控制流的逆向分析.md#条件分支).

多路分支可以不逐个比较, 而是把输入当数组下标, 从地址表中取出目标再 `jmp`:

```asm
mov rcx, [rsp+16]
xor eax, eax                 # 先清零, 否则高位残留
mov al, BYTE PTR [rcx]
mov rax, [rax*8+0x401088]    # 表基址 + 下标*8
jmp rax
```

逆向时的做法:

1. 表基址就是反汇编里 `rax*8+` 后面的常量(`objdump` 会把表数据误当指令, 忽略即可).

2. 在 gdb 中 `x/256a 基址` 看全部 256 项, 找出与众不同的那一项.

3. 下标 = (该项所在地址 - 基址) / 8, 即要输入的字节. 注意用左边的槽地址, 不是里面存的地址.

## 函数调用

`call target` 先把下一条指令的地址压栈(返回地址), 再跳转. `ret` 弹出该地址并跳回. 返回值放在 `rax`. 栈的基本操作见[栈的访问](栈与程序参数.md#栈的访问)与[函数调用与栈](x86-64汇编基础.md#函数调用与栈).

共享库里的函数只需 `.global` 导出符号:

```asm
.intel_syntax noprefix
.global solve
solve:
    mov rax, rdi    # 返回第一个参数
    ret
```

```bash
as -o solve.o solve.s
ld -shared -z noexecstack -o solve.so solve.o
```

- 调用者通过 `dlopen` 加载, 路径要写 `./solve.so`, 不带 `./` 会去系统库路径找而失败.

- 没有 `.note.GNU-stack` 节时, 链接可能需要 `-z noexecstack`.

- 调试: 另写一个带 `_start` 的文件, 构造参数, `int3` 后 `call solve`, 再用 gdb 单步. 也可 `gdb --args /challenge/harness ./solve.so`.

- 参数用 `rdi`, `rsi`, `rdx` 等传递, 与[系统调用](IO与系统调用.md)前几个寄存器相同, 但 `write` 需要的顺序不同, 要先搬运.

- 回调函数指针的概念见[函数接口](../c/函数接口.md).

## 调用约定

[System V AMD64 调用约定](x86-64汇编基础.md#System-V-AMD64-调用约定)把寄存器分为两组:

| 类型 | 寄存器 | 谁负责保存 |
| --- | --- | --- |
| caller-saved | `rax`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`-`r11` | 调用者, 调用前 `push`, 调用后 `pop` |
| callee-saved | `rbx`, `rbp`, `r12`-`r15` | 被调用者, 用之前 `push`, `ret` 前 `pop` |

要点:

- 调用回调且参数也要用 `rdi` 时, 先把函数指针挪到 `rax`, 再 `mov rdi, 1337`, 最后 `call rax`.

- `pop` 顺序必须与 `push` 相反, 且 `ret` 前 `rsp` 必须正好指向返回地址.

- 执行 `call` 之前 `rsp` 应是 16 的倍数. 进入函数时 `rsp % 16 == 8`(返回地址占 8 字节), 所以压入奇数个寄存器后恰好对齐, 偶数个(如 6 个)则要 `sub rsp, 8` 补齐, 调用后 `add rsp, 8`.

```asm
# callee-saved: 借用 rbx 等六个寄存器
push rbx; push rbp; push r12; push r13; push r14; push r15
mov rbx, 0x1337   # ... 其余同理
sub rsp, 8
call rdi
add rsp, 8
pop r15; pop r14; pop r13; pop r12; pop rbp; pop rbx
ret
```

## 常见误区

!!! warning "常见误区"
    - 以为 `cmp` 会修改操作数. 它只改标志位.
    - 查表前不清零 `rax`, 只写 `al`, 高位残留导致下标错误.
    - 把表项里存的地址当成下标计算, 应该用槽地址减基址.
    - 用 `rdi` 放函数指针又想用它传参, 指针被覆盖.
    - `push` / `pop` 不配对或顺序不反, `ret` 跳到错误地址.
    - 忘记 `call` 前的 16 字节对齐.
    - `dlopen` 路径不写 `./`.
